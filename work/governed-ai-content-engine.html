Designed and built a governed, multi-agent AI production system.

I evolved an end-to-end content workflow into a coordinated production operation running across separate machines. A primary AI coordinator manages context, exceptions, and system oversight while a dedicated production agent executes the resource-heavy video workflow. Configurable guardrails keep people in control when risk requires it and allow trusted workflows to run autonomously when policy permits.

The problem

Scaling output was easy. Scaling judgment was not.

A private ecommerce portfolio needed a repeatable way to produce platform-appropriate, brand-aligned short-form content across multiple brands. A chain of disconnected AI tools could create more output, but it could not guarantee that approved words stayed unchanged, visuals remained usable, costs were controlled, or publishing stayed under human authority.

The real design challenge was not “make a video with AI.” It was to create one governed production system where research, generation, review, verification, drafting, publishing, and learning worked as a controlled whole.

The architecture

Automation between decisions—not instead of decisions.

The production line below shows the governed operating mode. Gold stages require an explicit human decision; green stages run automatically. The gates are configurable, so trusted workflows can reduce or lift them and let the same pipeline run end to end autonomously.

The multi-agent evolution

Coordination stays responsive. Production gets its own lane.

The original workflow grew into a multi-machine operating model that separates oversight from execution. The active production path uses two coordinated Claude Code environments: a primary coordinator protects context and handles exceptions while a dedicated producer claims and completes approved video work. A Hermes agent is also connected to the shared agent network—the hive—and has passed integration testing, but it has not yet been assigned active production work. The architecture can add specialized workers through the same shared state, task claims, ownership locks, handoffs, budget controls, status reporting, and recovery model as production demand grows.

01

Exclusive ownership

Explicit claims, locks, and single-producer rules prevent two machines from acting on the same production task.

02

Recoverable work

Heartbeats, stale-run detection, and orphan recovery make stalled or abandoned work visible instead of silently losing it.

03

Governed authority

Agents can request a decision, but protected actions stay operator-controlled in governed mode. Those gates remain configurable by policy.

04

Tested expansion path

An additional Hermes agent is connected to the shared agent network and has passed integration testing; it remains staged rather than assigned active production work.

Validated under real production constraints: every documented completed production with recorded spend stayed within its configured budget ceiling. Generation spend is counted when work is submitted—including re-renders—and the workflow stops rather than authorizing work that would breach the limit. The ceiling can be adjusted as production type, quality requirements, and campaign priorities change.

Design principles

The guardrails are part of the product.

The system was designed around practical operating rules, not a promise that a model would always behave correctly.

01

Make it cheap to say no

Review scripts and low-cost stills before expensive production work begins.

02

Lock what was approved

Downstream steps cannot silently rewrite the words or visual plan a person accepted.

03

Fail closed

If required verification cannot pass, the run stops and reports instead of guessing.

04

Reserve authority for people by default

In governed mode, the system can prepare a draft but cannot publish or mark its own work approved.

05

Turn misses into rules

Rejections and observed defects become reusable constraints for future production.

06

Make autonomy configurable

Approval gates are policy controls. They can be reduced or lifted so trusted workflows run fully autonomously.

What I built

One operating system, not a pile of AI tools.

I owned the product and systems work needed to make the pipeline coherent from the operator’s point of view.

Workflow and product design

Mapped the production lifecycle, decision rights, approval states, failure states, and operator experience.

Multi-agent orchestration

Separated coordination from execution, defined machine responsibilities, and connected handoffs, claims, status, and recovery into one operating model.

Operator control plane

Created a shared view for agent conversations, approval requests, machine activity, task ownership, and scheduler status.

Quality and governance

Designed source-of-truth rules, transcript comparison, visual inspection, budget boundaries, and configurable release authority.
